# 悬停计算详情与原型选择边界

本轮保留 Svelte 前端与现有 IPC 命令。Rust 负责原型含义、品质与计算基础值；前端负责布局、单位格式化和索引筛选。把界面迁回 Rust 或另加 WASM 运行时会涉及控件、状态与打包重做，当前没有必要。

## 消息分层

- `catalog_index.entries[].tile`：仅地格条目携带 `{ fluid, destroys_dropped_items }`。`fluid` 为空或引用不存在时不可抽取。前端用这份索引直接过滤，不逐地格拉取详情；可达性设置不会绕过物理能力过滤。
- `prototype_detail.calculation.stats`：与品质无关的计算信息。
- `prototype_detail.calculation.qualities[]`：每个品质的 `quality` 和 `stats`，一次请求缓存，切换品质不重新请求。
- `stats[]` 使用 `{ key, value, unit }`；`key` 是稳定语义键，`unit` 为 number / seconds / watts / joules / joules-per-degree / percent / multiplier / per-second。百分比传入比例值，功率传入 W，不混用 J/tick。
- `prototype_detail.calculation.tile` 与索引共用 core 的 `tile_capabilities` 查询，避免前后端重复定义规则。
- `ingredients[]`、`results[]` 保留期望数量、概率、原始数量范围、可产能基数、品质和温度信息，新增速度 1 的 `base_rate`；它不代表当前工厂的实际速率。
- 旧的详情标量字段保留兼容，前端统一合并计算字段；科技的研究单位数、单次时间与科技瓶需求、星球/地表的原型属性也分组传递。表面属性保留用于条件匹配的原型数值，不假定未知模组属性的单位。当前用量缩放后的流量由机制卡传递，并标记为实际结算或单位机制流量。

模块品质效果、插件槽、虚拟科研和比热等使用已有 Rust 辅助方法。机器速度尊重原型对特定品质的映射；悬停明确标注基础值未计插件与工厂环境，避免把原型指标冒充完整机制求解结果。

详情缓存按上下文、kind、name 隔离，合并并发请求；清空缓存会使旧请求失效，防止旧响应回填。没有新增悬停专用 IPC 端点，也没有把计算拆成逐字段请求。

## 展示与选择

统一悬停卡采用双列指标、原料/产物紧凑明细行，保留具体概率、产能有效基数、品质限制和温度。抽象能量、运力、污染及虚拟科研也有说明。卡片可进入、滚动和选取文字；避让鼠标与窗口边界，打开编辑浮层时关闭旧卡，并始终只显示一张。

地格选择以名称和用途列表展示：抽取选择器仅显示有有效流体的地格，销毁选择器仅显示允许销毁物品的地格，且搜索和确认路径共用过滤规则。销毁机制有独立的地格选择图标。Rust 消息校验同样拒绝无效选择，GUI 与 MCP 共用。

这里过滤的是物理用途，不额外限制用户手动配置为当前星球自动可达地格；自动枚举的环境推导仍由原有逻辑负责。

## 验证

- Rust：真实原版数据的数值可序列化检查、品质覆盖值、模块效果、普通物品与 tool 科研容量、默认比热、抽水速率、概率产物基准速率、索引/详情能力一致性、地格消息校验。
- 浏览器：`pnpm test:layout` 增加品质悬停、品质切换缓存、实际功率、重复产物、概率/产能、可进入和缩放避让、抽取/销毁筛选与无额外详情请求，保留 1000 行机制回归。浏览器使用模拟 IPC，Rust 测试验证真实原型与计算数据。
