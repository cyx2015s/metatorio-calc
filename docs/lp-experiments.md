# lp-exp：原模型校验与支持集重求实验

本地分支 `lp-exp`。目标是建立可以重复验证的难例，发展 Rust 的数值修正、证书和搜索内核，最终替换当前应用求解路径。现已有独立 Rust 精确 LP 实验内核，全量难例稳定性和生产集成仍在推进。

阶段更新：现已提取独立的 `metatorio-lp` Rust crate，支持精确两阶段求解和基更新；默认应用后端仍是 HiGHS。以下各阶段保留当时的测量和适用范围，最新状态见第三阶段。

## 已建立的实验入口

- `metatorio-solver` 的 `lp-experiments` 功能：捕获原始目标、连续变量边界、约束、变量/行标签与生产 RHS 缩放。浮点值按 `u64` 位模式保存，支持无限边界。
- `METATORIO_LP_CAPTURE_DIR` 指定输出目录。每次求解使用独立文件，捕获失败只记录错误，不改变求解结果。
- 独立回放工具：保存解、对偶、基状态、后端状态、加载后非零系数数目、配置和迭代数。
- 原问题验证：补偿乘积与求和、变量边界、原始行活动量；对偶检查包含驻点、符号、互补条件和目标差。这些属于浮点诊断，尚不是精确证书。
- 24 个历史请求已固定在 `crates/metatorio-shell/src/mcp/auto_plan_assets_tests/fixtures/lp-failure-requests.jsonl`。诊断采集测试会记录真实 MCP 流程的成功/失败；测试通过只表示采集成功。成功请求另有回写与同步重求断言。

默认功能下的生产求解算法、重试条件、容差和回写行为未调整。实验重求结果尚未接入生产流程。

## 第一轮结果（2026-10-13）

数据源为本地 `assets/data-raw-dump.json`，链接的 C++ 后端为 HiGHS 1.15.0。上游源码克隆位于 `playground/HiGHS`；演进和 AI 重写案例研究位于 `playground/highs-research/RESEARCH.md`。

24 条历史请求记录重跑后，真实流程完成 2 个、失败 22 个。其中有一条重复请求，共 23 个不同请求；保留重复项以追踪报告来源。成功数会受到变量枚举顺序和数值路径影响；所以后续比较使用冻结矩阵，而不是每次重新构造游戏模型。

冻结模型从 2,032 到 163,398 个变量。默认路径中，20 个返回 Optimal 但未通过原模型行校验，4 个返回 Unknown。失败样本反复出现核燃料供应行缺口；Unknown 的候选还可能违反非负边界。Unknown、超时及未经原模型校验的 Optimal 均不可当作不可行或已解出的结论。

史诗级生物室的冻结 LP（131,249 变量）：

| 路径 | 状态 | 原模型行校验 | 备注 |
|---|---|---|---|
| 默认 | Optimal | 最大相对违反 1 | 核燃料供应缺口约 4.88e-8 |
| 关闭缩放 | Optimal | 通过 | 目标值约 74285.61487397 |
| 关闭缩放及 presolve | Optimal | 通过 | 同一目标值 |
| 收紧容差、保留更小系数 | Optimal | 失败 | 核燃料缺口约 1.95e-7 |
| 收紧容差、关闭 presolve | Optimal | 通过 | 同一目标值 |
| 不放大 RHS | Optimal | 通过 | 同一目标值 |
| IPX + crossover | Optimal | 失败 | 收紧容差也没有消除缺口 |
| IPX、不做 presolve | 超时（20 秒） | 失败 | 不代表不可行 |
| 支持集重求 | Optimal | 通过、边界违反 0 | 131,249 → 76 变量 |

缺口对应的虚拟燃料流约 4.88e-8，同时连接真实燃料流约 1.22e-15；后者乘以约 4e7 的系数。供应行的几个核反应堆变量为 0，系数约 -8e9。这里的小变量有跨行连接，不能仅凭数量级删除。单列零成本归零实验在真实样本上没有修复这一问题。

## 支持集重求的定义与限制

1. 从完整模型取得候选解。未终止时尝试关闭缩放和 presolve；优先选择 Optimal，否则保留原模型行/边界违反较小的有限候选。候选只用于选择变量。
2. 保留所有精确非零的候选变量；没有按流量大小设截断阈值。
3. 保留不能取 0 的变量，以及未通过原模型行校验的每一行中的所有变量，让缺失的供应方可以进入子问题。
4. 其余变量固定为 0，所有原始约束保留，重求连续 LP。
5. 将解映射回完整模型，重新检查原始行、边界、有限性与目标值。

最终统一回放中，24/24 个冻结模型均返回 Optimal，完整原模型的行检查全部通过，边界最大违反均为 0；支持集为 22–208 变量。汇总位于 `local/lp-exp/corpus-20261013/replay-support-refine-20261013-084337/summary.json`。

最后一个传奇级堆叠机械臂模型也体现了路径差异：关闭缩放并关闭 presolve 报 Unbounded，但其有限候选的行/边界误差较小；不放大 RHS 的完整模型路径返回 Optimal 且通过数值校验。使用更好的有限候选构建 133 列支持子问题后，返回通过原模型校验的解。支持重求的目标值约 1060533.407557，另一完整模型路径约 1060532.999503；这项差异也说明当前结果只能用于可行性修复实验，还需原模型定价与精度修正来评估最优性。

这里的行预算沿用生产判断 `abs <= 1e-6 * max(sum(abs(a*x)), abs(b)) + 1e-8`，此外实验汇总要求边界最大绝对违反不超过 1e-8，状态为 Optimal，所有活动量有限。通过意味着符合这组数值预算，不是数学意义上精确满足约束。限制子问题的最优值也不证明原模型全局最优；工具明确保存 `global_optimality_verified: false`。

`small_matrix_value` 必须在 `Highs_passLp` 之前设置，否则系数在载入时已被删除。回放现在先配置空模型再载入 CSR，并记录加载后的非零数。较低的 1e-12 阈值仍可能删除更小系数，因此必须验证原始矩阵。

## 下一阶段的验收顺序

1. **完整流程修复实验**：将支持集候选接入 opt-in 求解路径，保留原模型验证，跑所有 24 个请求的真实回写与同步重求；再覆盖正常、不可行、小目标和重模组样本。不能把冻结 LP 的通过数当作完整流程通过数。
2. **Rust 精度修正层**：读取小子问题的基，重构基础矩阵，使用更高精度/有理数重求原始解与对偶；退化或奇异时换基。优先利用现在几十到两百列的子问题，避免直接对十几万列做高成本运算。
3. **原模型定价与证书**：对完整候选列计算 reduced cost；存在改善列时扩展支持集。只有完整原始矩阵的可行性、对偶可行性和目标界共同成立，才升级为已验证最优。
4. **独立 Rust 搜索内核**：逐步实现稀疏存储、基分解/更新、修正单纯形、退化处理和可逆 presolve。每替换一个模块，都运行冻结矩阵差分；保留 HiGHS 作参照。

首个更高精度版本的成功条件应是：目标样本完成真实回写，数值不确定与不可行分开报告，保留必要的微小流量，并提供可审查的残差/证书。更强大的 LP/QP/MIP 功能在这个基础稳定后逐步扩展。

## 第二阶段：Rust 精确基与精确单纯形（2026-10-13）

新增 `rational-lp` 功能和 `lp_rational` 模块。这个核心没有 HiGHS 调用：

- 使用纯 Rust 大整数/有理数重新构造基础矩阵，消去基本行松弛变量，精确求出原始解和行对偶。
- 检查每条原始行、每个变量边界，对完整候选列进行精确定价；只有原始可行性、对偶可行性及目标差严格为 0 时标记最优。
- 全量定价使用共享分母整数运算，避免每个矩阵乘积都约分；覆盖最小非零浮点、最小正常数、极大值和普通小数的独立有理数对照测试。
- 实现针对应用当前变量形式的精确原始单纯形：变量下界 0、无有限上界，等式与 `<=` 行；用 Dantzig 选列，检测到重复基后永久切换到 Bland 选列。
- 返回无界前独立验证精确改善射线。换基上限或外部停止保留当前可行解、基和非终止原因，可以继续求解，不转换为不可行。

输入语义是捕获的 `f64` 模型的**精确二进制有理数值**，不是从游戏原始数据恢复的十进制或整数比例。最终转回 `f64` 时仍有舍入；精确证书对应保存的有理数解。`metatorio-solver` 目前整体仍依赖 good_lp/HiGHS，Rust 核心本身不调用它们；独立求解 crate 的提取仍待完成。

### 第一个完整模型的 Rust 精确最优证书

对请求 4（稀有品质插件塔设置、Fulgora、普通电磁工厂目标）的 **2,032 变量、373 行完整模型**运行 Rust 精确单纯形。初始候选基来自上一轮已保存的 22 列支持 LP，这次运行没有调用 C++ 求解：

- 仅 Bland 选列在 120 秒内执行了 422 次换基，尚未收敛；该实验报告非终止，未报不可行。
- Dantzig + 重复基检测退路执行 99 次换基得到完整模型精确最优证书，初测 19.13 秒、最终版复跑 30.27 秒，本例没有触发 Bland 退路。
- 完整原始约束和边界严格满足，对偶符号严格满足，精确目标差为 0。
- 转成 `f64` 后目标值约 `3988.917887719224`，通过原应用行校验且无边界违反。
- 另有经典退化循环样例实际触发重复基检测/Bland 退路，并得到精确最优解；无界射线、有限上界证书、微小缺口和非终止恢复也有测试。

证据位于 `local/lp-exp/corpus-20261013/replay-support-refine-20261013-084337/request-4/rust-simplex-final.json`；该文件保留完整基、精确非零原始解、行对偶和原模型证书。

## 第四阶段：精确对偶可行基修复

`metatorio-lp::Model::repair_dual_feasible_basis` 在严格对偶可行的候选基上执行精确对偶单纯形。结构变量负值、基本不等式松弛量负值、固定为零的等式松弛量正负违反均可修复；比值检验用大整数交叉乘积比较，平局按变量编号选择。重复基、观察者取消和换基限额保留未完成候选，不将其宣称为可行。比值检验无进入变量时必须独立验证原模型 Farkas 证书。

修复路径按需求解基转置方程以获取离基变量的线性泛函，不预先计算完整基逆；原始单纯形继续复用基逆更新。这个取舍适合只有少量微小违反的候选基。每步独立重构和精确校验仍保留。

`lp_certify` 增加 `--repair`（修复支持模型并验证完整原模型）和 `--repair-solve`（修复后在完整候选模型上继续优化）。输出分别保存支持模型和完整模型证书。支持模型不可行证书会再次对完整模型定价，只有验证通过才填写 `full_infeasibility`。修复尚未获得可行解时不会启动原始单纯形。

新增 5 项测试覆盖双侧等式违反、结构/松弛变量进入退出、微小 RHS 的精确比值选择、不可行证书和非终止限额；核心现有 17 项测试全部通过。应用求解器 30 项实验特性回归测试通过。

## 第五阶段：真实回写接入与无候选基冷启动

实验特性 `lp-experiments` 下，环境变量 `METATORIO_LP_BACKEND` 可选择：

- `hybrid-exact`：HiGHS 搜索支持集和候选基，Rust 精确修复并验证完整模型；接受严格可行解，完整候选模型最优性单独记录。
- `rust-exact`：完整模型直接由 Rust 对偶单纯形从零启动，不读取支持集或候选基，也不调用原生候选搜索。只接受完整模型精确最优证书；当前要求非负目标成本、非负无上界变量。
- 未设置或 `highs`：保留原默认后端。

两条实验路径在返回应用前均进行完整精确校验、转回 f64 后的独立预算校验及原应用校验。`SolveDiagnostics` 新增 `exact_primal_verified` / `exact_optimality_verified`，描述返回工厂的 LP；自动规划结束后这是回写后的机制集合，不能把它当作全部候选机制的全局最优证据。全部候选模型的检查另见实验日志。

`Model::solve_dual_with_observer` 利用非负目标成本下全零结构变量与零行对偶的对偶可行性，从全基本行松弛变量启动；固定为零的等式松弛变量初始可违反正侧或负侧。由此不需要人工变量 Phase I。冷启动从空基逆开始更新，暖基修复仍按需解方程，避免初始化稠密基逆的高成本。四类基交换的缓存线性泛函与独立转置方程求解作精确对照。

完整 2,032 变量电磁工厂模型无需任何候选基即可求得精确最优解：211 次换基，按需重分解版 56.80 秒，基更新版 13.37 秒。本机单次测量，分别保存为 `local/lp-exp/dual-cold-full-4.json` 与 `dual-cold-cached-full-4.json`。这解决了此前同一完整模型 Phase I 在 120 秒内仍未结束的冷启动例子。新增生产链、微小 RHS、冷启动不可行证书与负成本拒绝测试；核心现有 18 项测试通过。

```powershell
# 真实规划与回写，所有选择的请求必须完成。
./scripts/lp-experiment.ps1 -Backend hybrid-exact -PipelineOnly -RequireSolved

# 纯 Rust 完整规划与回写，先选择已完成冷启动的电磁工厂例子。
./scripts/lp-experiment.ps1 -Backend rust-exact -PipelineOnly -RequireSolved -RequestOffset 4 -RequestLimit 1

# 单个完整模型的独立冷启动诊断，不接收支持集/候选基参数。
cargo run --release -p metatorio-solver --features lp-experiments --example lp_dual_from_zero -- $snapshot $output 120
```

真实纯 Rust 端到端请求 4 已通过，证据目录 `local/lp-exp/rust-pipeline-4`：完整规划 211 次换基、13.97 秒，回写后的三次小模型重解各 21 次换基、约 0.06 秒，全部具有精确最优证书；整个请求 14.24 秒。冷启动精确目标值与先前 Rust 热启动完整最优证书完全相同。纯 Rust 实验后端下现有 30 项求解器测试也全部通过。

规模限制仍存在：请求 0 的完整 99,100 变量模型直接冷启动，在 120.18 秒、484 次换基时仍只有对偶可行基，尚未原始可行。输出 `local/lp-exp/dual-cold-cached-full-0.json` 明确记录非终止限额，未声称不可行或最优。

初次混合后端实际回写回归（`local/lp-exp/hybrid-pipeline-24`）前 15 个请求完成，请求 15 因大基重复精确求解触发应用 120 秒超时。保留该失败证据，没有修改应用超时。后续将精确 Gaussian 消元主元行改为当前列非零候选中剩余非零数最少的一行，并跳过零乘积，减少填充；所有计算仍为精确有理数。冻结模型请求 15 的重构由 34.96 秒降至 2.08 秒，请求 10 的修复由 35.17 秒降至 3.33 秒，请求 2 由 10.84 秒降至 1.28 秒。新证据为各单例目录下 `dual-repair-sparse-pivot.json`。

优化后的完整实际回归 `local/lp-exp/hybrid-pipeline-sparse-24` 中，请求 0–22 全部完成、回写验证通过，最长 27.06 秒；曾超时的请求 15 在 22.12 秒完成。请求 23 此次生成的候选基不是严格对偶可行，故整批严格门禁失败（23 done / 1 failed），失败不是模型不可行证明。

随后补全候选基分流：先精确重构；原始可行时直接进入完整模型验证，原始不可行但对偶可行时用对偶修复，两者均不可行时在支持模型内从零运行 Rust 对偶单纯形。新增两个单元测试分别验证原始可行但非最优时保留正确证书，以及双侧不可行候选被冷启动替换。求解器实验特性下现有 32 个单元测试，其中新增两项已独立执行通过；之前 30 项在纯 Rust 实验后端下通过，默认后端 25 项通过；核心 18 项及全部目标 Clippy 通过。

请求 23 的单独复测 `local/lp-exp/hybrid-pipeline-23-classified` 完成真实回写，耗时 50.96 秒，但该次产生的是原始/对偶均可行的新候选，不能用此结果证明先前具体异常候选已被复现修复。当前是跨运行合计 24 个请求均有回写成功证据，尚未在最终分流版本上连续完成同一批 24 条严格门禁。需要继续最终版本整批与重复回归、保留异常候选基、扩展纯 Rust 大模型冷启动/全局最优性验证。默认生产后端仍未切换。

## 第六阶段：完整回写门禁、候选留档和冷启动策略对照

同一分流版本首次连续通过全部 24 条请求的严格实际回写门禁，证据为 `local/lp-exp/hybrid-final-with-candidates`：24 done / 0 failed，24/24 回写验证、24/24 返回工厂精确原始可行性验证，最长 34.742 秒。该目录 `summary.json` 保存逐例结果。一次完整通过尚不代表覆盖全部随机输入；完整候选模型最优性仍与回写后模型最优性分开。

捕获模式现在在 `candidates/` 子目录按原始快照同名保存实际受限快照、所选列、原生候选基及搜索状态，在精确重构之前写入，拒绝的基也可保留。该次共保存 96 个实际候选（含回写重解）。其中 61 个初始原始/对偶均严格可行，35 个初始原始不可行而对偶可行；没有出现双侧不可行候选，相关回退仍由单元测试覆盖。请求 2 的留档候选已通过 `lp_certify --repair` 独立重放：1 次换基、约 1.37 秒、完整模型严格可行，无需重新调用原生搜索。

新增 `solve_dual_with_rule` 及诊断入口参数 `first` / `largest` / `large-pivot` / `edge`。默认保持 `first`。分别为按编号选择违反量、最大绝对违反量、精确比值平局时优先较大主元，以及违反量平方除以基逆行范数平方的选行。加权方式参考已克隆 HiGHS `HEkkDual::chooseRow` 与 `HEkkDualRHS::chooseNormal` 中的边权计算/比较；本原型直接以精确整数公共分母重算范数，未实现 HiGHS 的增量边权维护与缩放。整数范数另与直接有理数表达式对照测试。

`edge` 大模型实验暴露了资源限额时丢失候选的行为：原先扩基超过上限会返回一般错误。现已让原始/对偶单纯形在扩基前保留当前解、基、换基次数并返回明确的维数限额停止原因；不可行或无界结论仍必须有证书。257 变量边界模型分别验证原始可行候选和对偶可行候选都被保留。核心现有 20 项测试通过，求解器 32 项回归通过。

这轮结果表明，调整换基规则可以改善特定样本，但尚未解决大模型纯精确冷启动的规模问题。下一步优先研究 Rust 内部的快速候选搜索与精确校验/修复组合，以及稀疏基分解；继续保留全模型证书与可重放候选，避免把支持集可行性替代全模型优化目标。
