# 机制流筛选

中栏工具条的“筛选”展开消耗、产出两个条件。点击“选择对象”后，可按本地化名称或内部 ID 搜索当前工厂机制展开中出现过的流。每个方向可选择一个对象，两个方向同时启用时取交集；单独清除某个方向后另一方向继续生效。

- 物品、实体默认“任意品质”，可进一步指定品质。物品与同名实体、虚拟科研分别匹配。
- 流体默认“任意温度”，可限定为缓存中出现的某个温度或温度区间。限定区间按完整区间相等匹配，不表示区间重叠。
- 电力、热量、污染、虚拟科研和抽象燃料等流同样可选。抽象燃料保留类别、燃烧产物等约束；它们不等于具体燃料物品。
- 匹配依据是系数为 1 的缓存展开净流量：负数为消耗，正数为产出，零不匹配。与实际求解用量无关，禁用或用量为零的机制也按自身展开结果匹配。同一流若在后端展开中已经抵消为零，前端不能恢复其原料/产物明细。
- 筛选发生在配方合并之前：合并组只包含匹配的变体，剩一个变体时显示单卡。关闭合并不改变匹配集合。
- 筛选只改变显示，不增删机制、不切换启用状态、不更改求解。筛选期间暂停手动拖拽排序，避免重排部分列表时丢失隐藏项；清除后恢复完整列表及其顺序。其他工厂级操作仍作用于整个工厂。
- 收起筛选面板时保留条件、匹配计数和读取状态，可从摘要清除筛选。切换工厂或项目时重置条件。

## 缓存与虚拟滚动

未使用筛选时继续按可见机制惰性展开，不预取全厂。首次展开筛选后，以每批 6 个请求补齐虚拟滚动尚未加载的机制，使用现有 `mechanic_flow` 接口，不新增后端接口、类型或求解过程。卡片与筛选共享缓存和正在进行的请求。

缓存身份包含上下文、项目、工厂、机制 ID；内容签名包含机制配置、项目设置和工厂环境，避免环境或品质、插件等改变后沿用旧结果。读取失败不缓存为空，可重试；成功的空展开正常缓存。新配置、清缓存后的请求不会被旧请求的成功或失败覆盖。

读取期间显示进度，结果逐步补齐；失败项单独计数并标为尚未判定。尚未读取或读取失败的机制不会混入确定匹配的卡片列表。

## 验证

- `pnpm test:mechanic-filter`：对象/品质/温度匹配、方向与交集、零流、异构流、请求去重、失败重试、旧请求和缓存清理。
- `pnpm test:mechanic-filter-browser`：真实 Svelte DOM，模拟 IPC；96 个机制覆盖未打开时惰性加载、离屏条目、合并变体、收起摘要、配置/环境变化、失败重试、顺序恢复及无文档写入。
- `pnpm check`、`pnpm build`，以及现有布局、选择器、本地化回归。

浏览器测试使用 Playwright，环境变量与现有布局测试相同；默认端口 5201，可通过 `UI_TEST_PORT` 修改。
