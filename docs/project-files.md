# 工程文件的打开与加载

## 文件与系统入口

默认保存为 `.metatorio`，文件内容仍是现有 JSON 格式，没有更改文档 schema。
旧 `.json` 和旧版 `.fpp` 仍可在文件对话框中选择，或作为启动参数传入。
安装包只声明 `.metatorio` 关联，不接管通用 `.json`。

Windows 支持将一个或多个文件拖到 EXE／快捷方式图标上启动，也可拖进已打开的窗口。
GUI 使用 Tauri 官方 single-instance 插件：已有窗口时转交文件并恢复、聚焦该窗口，
不再开一个争抢 MCP 端口的 GUI。无头进程不参与 GUI 单实例；无头打开工程仍使用 MCP 消息。

```powershell
metatorio-app.exe "D:\工程\我的工厂.metatorio"
metatorio-app.exe "a.metatorio" "b.json"
metatorio-app.exe --no-mcp "a.metatorio"
```

图标拖放本身不要求专用后缀；后缀关联用于双击打开和默认程序识别。
`.metatorio` 关联由新版安装包注册，便携 EXE 本身不写注册表。
本次开发验证不运行安装器，不修改本机默认程序。

## 加载链路

1. `launch.rs` 解析启动参数；转交时使用发送进程的工作目录解析相对路径。
2. `OpenRequests` 保存系统打开请求，通知只负责唤醒。前端先注册事件、完成初始化，再取队列，
   因而首次启动、界面尚未加载或连续拖入文件时不会丢请求。
3. 前端的 `openProjectPath` 串行处理请求，显示正在打开的路径。对话框与系统入口复用该方法。
   一个文件失败不会阻断同批其他文件，错误保留文件名和实际读取／解析原因。
4. GUI 的 `open_project_file` 与 MCP／消息 `OpenProject` 共用 shell 的文件打开实现：
   路径规范化、锁外读盘、按源文件串行去重、短锁导入并返回准确项目 ID。
   重复打开只切换到已有项目，保留内存修改；原项目的工厂选择仍有效时也保留。

## 审查后修复的边界

- 只为本次导入的单个项目登记保存路径，不再把已有未保存项目误绑到新打开的文件。
- 工程合集不登记单项目保存目的地，界面提示分别另存为，避免单项目保存覆盖整个合集。
- 另存为更新路径及源文件映射，随后打开旧文件会重新读盘，而不是跳回另存后的项目。
- 兼容 UTF-8 BOM；拒绝空合集、无工程字段的 JSON，以及比当前软件更新的 schema。
- 旧版迁移依赖当前游戏数据的品质与配方定义；没有数据时明确提示先加载对应数据，不静默猜测。
- 工程引用的上下文不在本机时仍保留工程，并提供“选择游戏数据”入口；状态栏不再冒充使用其他激活上下文。
- 目录请求按上下文合并，过期上下文的目录或错误不会覆盖当前工程；加载失败可在后续切换时重试。

## 验证

Rust 测试覆盖参数解析、原生请求队列、真实临时文件、并发和别名去重、未保存项目路径隔离、
合集、错误文件／目录、BOM 以及另存为映射。
`pnpm test:project-files-browser` 使用真实 Svelte 界面和模拟 IPC，验证启动前排队、加载反馈、
重复打开的选择保持、失败后继续、缺失上下文提示、迟到目录响应和对话框复用。
它不代替 Windows 安装包关联的手动端到端测试。
