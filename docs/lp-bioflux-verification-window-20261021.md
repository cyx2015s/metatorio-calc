# 外部 bioflux 输入触发的自动规划变慢（2026-10-21）

## 样例与备份

原文件 `D:/异星工厂/calc/严格输出混品粉瓶.json` 已原样备份为 `local/strict-mixed-pink-backup-20261021.json`。两者 SHA256 均为 `64AD144E542A605022F099AAE1437EC9D146D778128A7BE45B880D92AE61C049`。未修改用户原文件、已有工厂或游戏上下文缓存。

研究的是工厂2665“插件”：Fulgora、传说品质插件3（quality-module-3）1/s，严格供给和严格输出，传说机器与速度/产能/品质插件，插件塔1/8/1及8/8/16。项目实际上下文为 vanilla 2.1.19（id `0ac4e1f02224603e`）。`preserve_existing_mechanics=false`，保存的208个机制不作为自动规划的保留候选。

`local/modules-bioflux-with-20261021.json` 与 `...without...` 仅把该工厂移到首位以适配通用重放测试；两者唯一业务差异是普通品质bioflux（输入3081，penalty160）是否存在。其余工厂、目标、严格模式、枚举配置均保留。

## 原因：正确候选在证书生成过程中被短预算打断

release基线：

| 项目 | 无外部bioflux | 外部bioflux价格160 |
| --- | --- | --- |
| 全模型列/行 | 202885 / 1641 | 202886 / 1642 |
| 首轮浮点换基数 | 4625 | 4675 |
| 首轮浮点时间 | 25.378s | 25.042s |
| 初始基的基本列数 | 1294 | 1294 |
| 单独精确重建该基 | 3.319s | 27.474s |
| 精确点非零列数 | 211 | 246 |
| 精确原始/对偶可行、最优 | 均是 | 均是 |
| 原模型最优成本（f64显示） | 4989.697000259589 | 4895.218030730269 |

加入输入只多一列一行，浮点阶段时间和迭代数接近；但得到的基在精确重建时明显更贵。旧代码把浮点搜索与精确验收一起塞入首轮45秒：25秒搜索后仅剩约20秒，不足以完成约27秒的重建。这会丢弃一个实际上已精确最优的候选，继而触发奇异基重试和完整模型列生成。本例不是精度预算太严、无解或枚举空间爆炸。

无输入的基线完整规划43.806s成功。有输入基线运行169.536s后停止，仍在列生成，没有终止结论；不能记作无解。计时是单次诊断，期间有少量工具/编译竞争，不能视为稳定统计值，但保存候选的单独重建证明确认了上述机制。原始证据位于 `local/modules-bioflux-baseline-*`、`local/modules-hint-{without,with}-20261021.json` 和 `local/lp-exp/modules-bioflux-baseline-*/`。

## 修改与验收边界

- 正常完成浮点搜索、无数值诊断的候选，精确验收至少有独立45秒窗口；仍遵守1200秒总预算，并保留恢复阶段时间。未正常完成的浮点搜索不享受这一延长。
- 非负候选未被截断修改时，复用同一个点的原始精确证书；已经精确证明全部行可行时，不再重复扫描并计算零残差。
- 如果负值被截为零，旧原始证书必须失效并重新计算。实际输出f64转回有理数后仍检查完整原模型及逐行1e−12预算。
- 精确零模式仍可选，验收容差、目标成本、模型候选和无解证明规则没有放宽。

尝试了先在较小候选支持集上重建：原始点可行，但对偶没有通过完整原模型（至少12个改进列被列出），重建与检查也没有显示收益。因此没有把该实验加入生产路径。诊断工具 `lp_hint_profile` 支持保存浮点候选的直接检查及 `--compact` 对照；紧凑支持失败不能证明原模型无解。

## 后续实测

关闭编译后，使用release按同一配置串行完整重放，均启用LP捕获：

| 场景 | 旧版端到端 | 修复后端到端 | 修复后结果 |
| --- | --- | --- | --- |
| 不输入bioflux | 43.806s | 41.101s | 成功、回写验证通过 |
| 输入普通bioflux，价格160 | >169.536s，停止时仍未结束 | 110.669s | 成功、回写验证通过 |

有输入时，修复后的主规划LP55.66s、回写前自检24.04s、回写后重求23.83s，首轮直接取得精确原始/对偶可行及最优证书，没有搜索重试。最终成本4895.218030730266，最终f64逐行最大相对误差8.003484621628727e−17。无输入成本4989.697000259589、最大相对误差6.915517641886783e−17。两者均未扩大回写支持集。

这不是把有输入场景降到与无输入一样快：剩余差距主要是更昂贵的精确基重建，以及两次各约24秒的工厂校验/重求。回写验证仍保留；将来若复用这两步的结果，必须证明机制ID、变量、约束和工厂设置映射一致，不能直接跳过检查。

新增测试覆盖证书复用后的f64下溢拒绝、负值截断使旧证书失效，metatorio-lp 81项和metatorio-solver 38项通过；两crate的lib/examples Clippy（`-D warnings`）通过。

另一次伴随编译的修复版运行，浮点阶段只完成2701次换基就在49.19s停止，未正常产生候选，故不适用新的健康候选验收窗口。该运行已停止并单独记录，未当作无解或正式性能数据。
