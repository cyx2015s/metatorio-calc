# DualVar 对象引用与诊断

`FlowRef.svelte` 是前端实际流对象的统一展示入口；`dual-var.ts::presentFlow` 负责无 UI 依赖的显示模型。不要在各页面重复写流到图标的 switch，也不要把流提前拼成不可还原的名字或 Debug 字符串。

## 引用语义

- 物品和实体保留类型区别与品质角标；实体另有“实体”标识。
- 流体保留单点温度或温度区间。需要显示名称时，温度不重复打印两次。
- 虚拟科研使用原科研包图标并加“科研”标识，明确它是无品质的科研价值，而非一瓶物品。
- 物品燃料供给、需求共享燃料图形，但分别加“供”“需”标识；悬停区分燃烧产物和容纳燃尽产物的能力，并显示燃料类别。空类别集合明确显示为空集合，不误称任意类别。
- 火箭槽位、重量运力有不同标识；电、热、流体燃料和流体热量沿用各自图形。
- 污染、自定义和未指定流有独立的合成 SVG；自定义名称作为字面用户文本，不解析为游戏富文本或 HTML。
- 无名称的紧凑引用仍保留语义标识，名称和约束可从悬停详情及无障碍标签读取。原型详情使用已有缓存，仅在悬停或聚焦时读取。

`match` 未传入时表示具体 DualVar。传入 `{}` 表示匹配条件：物品/实体不限品质、流体不限温度；不能显示候选代表值的品质角标来冒充该条件。限定品质后才显示对应角标。“任意品质”使用星号，并在详情中明确说明。若展示普通品质属性作为参考，会注明它不限制匹配品质。

目标、显式/隐式外部输入、目标表达式、总流平衡、机制流量 chip、供需建议标题、直接流选择器、机制筛选候选和已选按钮、求解与操作错误列表均使用该入口。配方、机器配置和游戏富文本中的原型引用不等于 DualVar，不强制转换成流。

## 结构化诊断

Rust `metatorio_runtime::Diagnostic` 与前端 `RuntimeDiagnostic` 保持字段对应：

```text
code: 稳定的诊断类别
message: 文字原因，不包含需通过 Debug 反解析的流清单
no_provider: DualVar[]
no_consumer: DualVar[]
flows: DualVar[]（其他关联流，例如参数校验失败时的原始对象）
```

`DiagnosticView` 分组显示这些对象，可按本地化名称、内部 ID、品质、温度或流类别搜索，点击对象图标可查看现有供给/消耗建议。复制顶端错误时同时保留本地化说明和对象 JSON。

普通未求解状态本来就有 `no_provider`/`no_consumer`，直接使用结构化字段。自动规划失败、流参数校验失败改为保存 `Diagnostic`，并通过调度器、命令回执、Tauri dispatch 拒绝值及错误事件保留流对象。求解器剪枝描述只报告原因/数量，缺失流在原有结构化列表中保留；配方环境说明也不再输出条件结构体的 Debug 文本。

MCP 保留原有 `errors` 和自动规划 `error` 文本字段，增加结构化 `diagnostics` / `diagnostic`；异步规划诊断中的流集合沿用分页并报告总数与截断。dispatch 参数错误在 MCP error data 中附带诊断。未知或 I/O 等没有流对象的错误可继续是字符串，前端使用同一个诊断组件回退显示，不从文字中猜测物品 ID。

Debug 仍可用于日志、内部去重/LP 变量命名、测试失败输出；这不构成前端展示协议。

## 验证

- `pnpm test:dual-var`：全部 15 种流、具体引用/匹配条件、品质与温度、燃料供需语义、错误回退和复制文本。
- `tests/fixtures/dual-var.json` 由前端呈现测试和 Rust 序列化往返测试共同读取，验证两侧引用的是相同对象形状。
- `pnpm test:dual-var-browser`：真实 Svelte DOM，模拟 IPC；覆盖全部类型的引用、惰性详情、悬停和键盘聚焦、诊断搜索、结构化事件与 dispatch 错误、字面自定义文本及筛选任意/指定品质。
- 既有图标、富文本、本地化、筛选、选择器会话和 1000 行布局回归。
- Rust 测试验证流校验诊断、真实自动规划无供给失败、调度器到事件和异步状态的完整对象保留，以及命令收集的文字/结构化双回执。

浏览器测试默认端口 5202，沿用 `PLAYWRIGHT_MODULE`、`BROWSER_EXECUTABLE`、`UI_TEST_PORT` 环境变量。模拟图标缓存会回退为占位图，测试不声称真实模组图标的像素一致性。
