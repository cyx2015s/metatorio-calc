# 无历史种子的结构冷启动（2026-10-23）

## 范围与正确性

本轮初始列只从当前 LP 的矩阵、目标 RHS 和成本产生，不读取历史方案、
用户工厂中的现成路线、配方名称或物料名称。历史种子仅作为结果质量的参考。
结构选择是启发式，不是等价约化；未选列仍可通过后续全模型定价加入。
可行、最优、不可行均需原模型证书，取消和启发式失败不构成不可行证明。

实现分为三层：

1. `route.rs`：以输入为超边前提、产出为超边结果，估计来源距离和单位取得成本。
   正 RHS 等式目标先翻转方向。按有符号行模式选不同生产方向，再选配置变体。
   闭合循环不因没有外源而永久排除；零平衡等式的副产出同时请求处置。
   非零 RHS 目标不预先强制加入回收链，实际处置需求由子问题反馈。
2. `route_search.rs`：在小模型上搜索、恢复完整原基并精确认证。失败时按实际缺口补列，
   扩大方向与变体范围；最终允许完整列集。微小等式缺口用精确残差处理，
   小模型精确 Phase I 的乘子也只能用于补方向，不能当作原模型不可行证明。
3. `columns.rs`：精确改善列优先覆盖不同方向，遇到重复方向或未完成搜索时扩大批次。
   受限不可行时，为改善列补充供应/处置闭包。完整精确定价仍保留所有非零改善量，
   family hash 只影响加入次序，碰撞不会永久丢列。

距离/成本归一化只影响排序。系数、收益概率和精确价格不按阈值删去。
候选宽度是可逐步扩大的搜索参数，不是模型维度或可解性上限。

## 实际自动规划入口

`lp_hybrid.rs` 的首次尝试现优先做结构冷启动；取得原模型原始可行基后立即保留，
后续恢复不再先耗尽其它冷启动尝试，而是进入完整基列生成。
启发式失败或局部时间用尽回退原搜索，不更改最终接受预算。

同一用户项目及冻结上下文，`project_file_auto_plan_benchmark` 记录：

- `[LP-ROUTE] first_feasible_s=1.073505`，首轮 74 列、39 次换基。
  这是冷启动子过程时间，不含先前项目加载、枚举、LP 构造与捕获。
- 后续日志确认 `seed=true warm_basis=true`，以全部 39 个基本列继续；
  没有仅按 28 个非零变量重建并丢失原基。
- 精确主问题出现对偶未完成后，批次由 32 扩到 64；日志中原始边界/行违反仍为零。
- 181.21 秒外部终止时尚未返回完整规划结果或全模型最优证书。
  因此本轮已解决该输入的自动可行起点，尚未解决完整最优性搜索。

输入和上下文 SHA256 与上一轮相同；回放目录为
`local/lengden-cold-route-20261023/current-project-route/`。实验没有修改用户原文件。

## 通用小例子

使用独立构造的无种子 Snapshot 运行相同列生成入口：

| 案例 | 预期 | 实际证据 |
| --- | --- | --- |
| 多输入、1/8 品质收益 | 最优成本 10 | 原模型最优证书，成本 10 |
| 无外源闭合放大循环 | 最优成本 1 | 原模型最优证书，成本 1 |
| 闭合有损循环 | 不可行 | 原模型不可行证书 |
| 等式联产品必须处置 | 最优成本 7 | 原模型最优证书，成本 7 |
| 大系数与高成本替代路线 | 最优成本约 0.01 | 原模型最优证书，成本约 0.01 |
| 重复模块方向 | 最优成本 1 | 原模型最优证书，成本 1 |

另有代码回归覆盖 `2^-46` 等式超产处置、同签名的昂贵必要变体、宽搜索最终覆盖、
取消、总换基预算，以及浮点缩放失败时保留精确 Phase I 找到的可行基。
小例子用于检验关键性质，不代表对所有生产网络的性能保证。

最终验证：`cargo test --offline --release -p metatorio-lp -p metatorio-solver --lib --tests`
为 **203 通过、0 失败、6 忽略**。应用回放测试构建与两个诊断示例构建通过。

## 复现入口

```text
cargo run --release -p metatorio-solver --example lp_route_propose -- snapshot.json --auto output.json 60
cargo run --release -p metatorio-solver --example lp_route_propose -- snapshot.json --auto:4:1:2 output-wide.json 60
cargo run --release -p metatorio-solver --example lp_column_seed -- snapshot.json - cold-result.json 60 --cold
```

`--cold` 不读取第二个参数指向的任何文件；`--auto` 不读取外部种子。
`METATORIO_LP_ROUTE=0` 可停用路线提议，`METATORIO_LP_COLUMN_SELECTION=legacy`
可恢复原 top64 加列规则，用于独立 A/B；`METATORIO_LP_COLUMN_PROFILE=1` 记录首次可行与批次统计。
