# 百万变量／万行稀疏 LP：调研与首轮应用（2026-10-22）

## 问题边界

`n≈10^6、m≈10^4` 本身不足以判断哪种算法最快。还要看非零元素数量、行列度数、活跃基的维度、LU 填充、退化、系数跨度、所需精度与是否需要稀疏路线解。本项目同时要求小供应链不被绝对容差忽略，并保留精确认证，因此不宜只根据某篇论文的平均加速比直接替换算法。

本轮继续使用 `lp-exp`；不改插件枚举的既定降级规则，不收窄合法候选集合，不更改 `1e-12` 相对平衡验收政策及精确零模式。小型正确性案例与独立内核微基准代替长时间真实工厂矩阵回归。

## 一手资料与适用判断

| 路线 | 资料及发现 | 对本项目的判断 |
|---|---|---|
| 稀疏／超稀疏单纯形 | [Hall & McKinnon, Hyper-sparsity in the revised simplex method and how to exploit it](https://webhomes.maths.ed.ac.uk/hall/HyperSparsity/HyperSparsityOctober2002.html)，2005：不只原矩阵稀疏，线性系统解与矩阵向量积也可能稀疏，应让工作量跟实际支持集有关 | 首选工程方向。当前先应用到受限主问题提取；尚未实现论文的超稀疏三角求解 |
| 稀疏基因子与更新 | [Huangfu & Hall, Parallelizing the dual revised simplex method](https://link.springer.com/article/10.1007/s12532-017-0130-5)，2018；[作者综述与更新技术论文入口](https://webhomes.maths.ed.ac.uk/hall/NLAO18/) | 长期高优先级是稀疏 LU／更新，优先于盲目提高并发。当前浮点路径还维护稠密逆，不能把本轮改动称为已解决万维活跃基 |
| 按需产生列和行 | [Muter, Birbil & Bülbül, Simultaneous Column-and-Row Generation](https://optimization-online.org/2010/11/2815/)，2013：列引入新结构行时须共同处理完整性 | 适合大量插件配置；真正省掉前端枚举还需 runtime 列提供器，不能仅按首轮活跃路线永久删列。详见 [两阶段设计](lp-two-stage-column-generation-20261022.md) |
| 对偶稳定化 | [Gondzio, Munari & González-Brevis, Large-scale optimization with the primal-dual column generation method](https://optimization-online.org/2013/09/4035/)：用较居中的对偶解减少定价调用和震荡 | 有潜力，但不能只加平均对偶后就用它终止。需要分别维护启发式定价对偶和最终认证对偶，另做轮数与耗时对照；本轮未接入 |
| PDLP／PDHG | [Applegate 等, Practical Large-Scale Linear Programming using Primal-Dual Hybrid Gradient](https://arxiv.org/abs/2106.04756)，2021/2022：核心为稀疏矩阵向量乘，结合预处理、缩放、步长和重启 | 适合超大规模、内存受限的近似求解或候选生成；达到本项目特殊逐行精度和可靠证书仍须验证，不能把论文 `1e-8` 指标直接等同本项目验收 |
| 混合精度与精确修复 | [Gleixner, Steffy & Wolter, Iterative Refinement for Linear Programming](https://optimization-online.org/2015/06/4948/)；[Eifler & Gleixner, Combining Precision Boosting with LP Iterative Refinement](https://optimization-online.org/2023/11/combining-precision-boosting-with-lp-iterative-refinement-for-exact-linear-optimization/) | 支持保留浮点搜索＋精确认证的总体方向；当前实现不能据此宣称已经完整复现论文算法 |
| 算法、缩放和精度取舍 | [Google OR-Tools, Advanced LP Solving](https://developers.google.com/optimization/lp/lp_advanced) | 一阶方法内存较省，但高精度和数值问题需关注；单纯形的顶点解有利于少路线输出。缩放必须与原模型回验配套 |

结论是分层优化，而不是把全部方法堆上去：先减少重复矩阵遍历，保留认证；再按测得瓶颈推进稀疏因子、惰性枚举或稳定化。资料中的并行、内点、PDLP 适合不同工作负载，不存在组合后必然解决全部难例的保证。

## 本轮已接入的优化

### 1. 受限主问题按稀疏支持集提取

过去列生成每轮都创建全列位置表，并扫描完整矩阵来找相关行、复制所选条目。完整变量／非零元素很多、选中列很少时，这项工作与“小模型”的规模无关。

新增 `crates/metatorio-lp/src/restricted.rs`：

- 小支持集首次需要时，构造压缩列关联索引；后续轮次复用。
- 根据所选列只访问相关原矩阵条目，按原始条目位置恢复每行顺序。
- 非零 RHS 的行始终保留；零 RHS 且没有参与非零系数的行才可省略。
- 保留重复项、显式零、负零与原始累加顺序，不作浮点聚合。
- 候选列或所选条目变密时，回退顺序行扫描。四分之一阈值仅选择提取策略，不限制模型大小或改变候选。
- 密集种子不构造索引；构造索引本身需要一次计数和一次填充扫描，收益取决于后续轮数。

索引在 64 位平台约需 `8(n+1)+16*nnz` 字节，构建时另有约 `8n` 字节游标。它是以附加稀疏索引内存换取重复扫描减少，并非总内存必然下降；当前尚未去掉完整 `Model`。稀疏提取路径另有与行数及所选条目数量相关的临时空间，避免每轮全列 `Option<usize>` 位置表。若全局定价或基更新占主导，这项优化的端到端收益可能有限。

### 2. 定价只部分选择所需列

完整精确定价仍检查全部列，使用相同整数分子和公共正分母，且仍保留任意小的负价。原来对全部改善列作 `O(q log q)` 排序后取前 64 个，现在先作部分选择，再只排序 64 个：`O(q + 64 log 64)`。

比较键仍是精确价格、原列 ID；因此返回的有序列集合与旧完整排序相同，包括并列情况。没有新增价格 epsilon、候选裁剪或终止捷径。改善列暂存向量仍是 `O(q)`，本轮未实现流式定价。

### 3. 复用已完成的完整证书

`scale_to_dual_feasible` 内部必须计算调整后解的完整证书；列生成调用方此前紧接着又为同一解计算一次。新增内部返回证书的接口供该调用方复用，公开接口行为保持一致。

这省掉该路径每次对完整解的一次重复认证，保留原始／对偶可行性、差距、不可行证书及终止判断。没有复用原始 hint 的证书，也没有把缩放前证书用于缩放后解。

## 小案例验收

新增检查：

- 小规模稀疏／密集两种提取策略逐项对照，涵盖乱序列、重复系数、大数抵消、负零、强制 RHS 行与取消。
- 极小负价 `1e-30`、并列价格和已包含列：部分选择结果与完整精确排序完全相同。
- 128 变量／8 行生产 LP，从昂贵种子开始，跨越稀疏提取和密集回退，补入遗漏便宜列后在完整模型认证目标为 8。
- 继续运行原有精确可行性、不可行射线、退化、相关性缩减等小型测试。

微基准显式标记 ignored，正常测试不作易受机器负载影响的速度断言。配置为 release、测试线程 1、七次交替执行取中位数：

- 提取：16,384 变量／512 行／65,536 条目，分别选 32、256、8,192 列，每组每次提取 20 遍；索引构造单独计时。
- 定价：16,384 变量／1 行／16,384 条目，每次运行 5 遍完整精确定价，比较部分选择与旧全排序。

这些规模远小于百万变量；微基准只说明具体内核的影响，不能外推为整个工厂的同比加速。索引构造成本须在判断收益时一并计入。

```powershell
$env:CARGO_INCREMENTAL='0'
cargo test -p metatorio-lp -p metatorio-solver --release --lib -- --test-threads=1
cargo test -p metatorio-lp --release --lib small_ -- --ignored --nocapture --test-threads=1
cargo clippy -p metatorio-lp --all-targets -- -D warnings
```

实际结果：release、单测试线程，LP 内核 **87/87**，上层求解器 **45/45**；两个 ignored 微基准另行执行通过，严格 Clippy 通过。正确性测试运行时间分别约 0.25 s 和 0.85 s，不含编译。日志保存在 `local/lp-sparse-research-20261022/`。

| 小型内核对照 | 顺序扫描／完整排序 | 索引提取／部分选择 | 比较口径 |
|---|---:|---:|---|
| 选 32 列，20 次提取 | 1.120 ms | 0.167 ms | 索引已建，约 6.7 倍 |
| 选 32 列，计入首次构建 | 1.120 ms | 0.920 ms | 20 次总计，约 1.22 倍 |
| 选 256 列，20 次提取 | 3.337 ms | 0.881 ms | 索引已建，约 3.8 倍 |
| 选 256 列，计入首次构建 | 3.337 ms | 1.634 ms | 20 次总计，约 2.04 倍 |
| 完整精确定价 5 次 | 9.537 ms | 6.005 ms | 包括计算全部精确价格，约 1.59 倍 |

该模型索引首次构建为 0.753 ms。因此只进行少数提取时，索引未必划算；按本次固定支持集数据，32 列约需 16 次、256 列约需 7 次提取才能摊平构建成本，不能仅引用热路径加速比。这里的顺序扫描参照使用当前 `by_rows`，不是整版本前后端到端对比。

密集探针（8,192 列）直接调用索引接口后回退，20 次为 12.968 ms，对照直接行扫描 11.475 ms；该探针没有优势。实际列生成调用处在选中列达到四分之一时直接调用行扫描，避开这个索引探测路径。这不证明密集实际场景无回退，只说明当前调度如何避免已测得的额外工作。

本轮改动的正确性依据是提取相同子矩阵、保留相同精确前 64 列、复用相同解的相同证书。没有假设纯插件足以保持最优，也没有把价格搜索范围缩到首轮使用的路线。

## 后续优先级

1. 真正的 runtime 惰性列提供器，避免先生成百万机制；全局定价与 Farkas 完整性一起实现。
2. 稀疏基因子与更新，替代浮点稠密逆；仅移除稠密资源保护不能解决活跃基上万时的时间／空间复杂度。
3. 根据轮次日志判断是否需要对偶稳定化、列池与更好的定价批次。保持最终原模型认证。
4. PDLP 可作为独立候选来源作实验，另测本项目精度下的有效性；不直接替换现有认证链。
