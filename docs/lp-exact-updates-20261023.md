# 精确换基增量更新与稀疏右端求解（2026-10-23）

本轮延续 `lp-sparse-exact-20261023.md` 的未提交实现，处理精确换基每步重建 LU 的成本。

## 实现

`basis::System` 使用完整基：结构基本列与基本 slack 的单位列合计为约束行数 `m`。
基础矩阵和 LU 仍然稀疏；基本 slack 的单列非零可由最小列度数主元选择优先消去。
记录基槽位与原始变量身份，因此结构列替换、slack 替换、结构基扩张与缩小都可统一为
固定 `m` 维基的一次列替换，无需构造或更新逆矩阵。

每次交换保存稀疏 eta：若 `B' = B E`，直接求解先应用原 LU 再顺序应用 `E⁻¹`，
转置求解逆序应用 `E⁻ᵀ` 后再求原 LU 的转置。最多 64 次交换重建稀疏 LU 并清空链。
另以各有理数分子、分母总位数的平方之和估算计算成本：eta 链超过当前因子权重一半
（小因子维护预算至少 64）即提前重分解。饱和整数只影响维护时机，不影响精确运算。
这些是维护策略，未增加模型维数、非零项数量或系数位数的拒绝上限。

原始优化和热启动对偶修复的公开入口允许自动选择增量路径，包括历史命名的
`optimize_without_inverse_*`。结构基本变量不足总行数一半时，继续使用较小的压缩结构因子；
随求解增长达到该比例后切换到完整基增量更新。该比例仅选择表示方式，所有基仍可继续求解。
私有强制 fresh 分支保留供回归对照。
同一基的 functional 和定价相关求解复用因子；即使处于压缩表示，SteepestEdge 也复用本轮
已有因子，避免为每个候选离基变量重新分解。增量初始化不再先完整重构再重复分解。

三角求解及 eta 应用跳过右端和解分量中**精确为零**的运算，避免对稀疏方向、零成本和
slack 右端做无用的大整数乘除；没有引入数值容差丢弃。

## 状态与验证

基础模型仍受现有非负无上界精确 simplex 合约约束。增量缓存只接受值为零的非基本结构变量；
构造和更新统一验证 `Lower`/`Upper`/`Zero` 的实际边界及非基行状态，避免热启动切换路径时
把无限上界或非零边界当成零。通用 `Model::reconstruct` 继续通过压缩结构基支持真实非零边界。

交换先验证完整基状态只发生指定的进入/离开，再局部准备 eta 或重分解因子；最后检查取消并提交。
非法交换、精确奇异或取消均保留旧基状态。循环、装配和大整数运算之间继续检查控制令牌。
单次大整数操作仍不能中途取消。

测试覆盖四种交换形状、140 次交换跨过两次维护周期、含非空 inactive 行的混合热启动基、
直接/转置/functional 对独立小型稠密 oracle、非法非基状态与失败更新原子性。
4097 维原始/对偶换基同时对私有 fresh 分解路径核对有理数原始解和对偶值。
另测含 `2^500` 系数的交换，确认大系数触发提前维护后仍得到独立 oracle 的精确结果。

只使用固定 64 次周期的初版在 ammonia 历史回放上从基线约 1.4 秒退化到约 4.7 秒，
状态及 Farkas 证明仍正确。加入相对系数复杂度维护策略后降到约 2 秒，再保留 slack 较多时
的压缩表示后恢复到约 1.35 秒。最终串行对照另列。

## 复现

```powershell
cargo test --release -p metatorio-lp -p metatorio-solver --lib --tests
cargo run --release -p metatorio-lp --example exact_updates_smoke
```

`exact_updates_smoke` 包含 128/512 行的热启动列替换和精确对偶链，每例有 30 秒控制期限，
断言精确最优目标值和预期换基次数，耗时不作为测试断言。
本机对照保留在 `local/lp-exact-updates-20261023/`：基线 crate 是本轮修改前、包含上一轮
全面稀疏化的工作区副本；单独离线编译同一 smoke，避免拿旧稠密实现冒充增量基线。
历史输入仍使用三份相同 snapshot，并通过独立 witness verifier 检查原模型。
