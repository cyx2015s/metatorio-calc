# 项目编辑与大型工厂的页面开销（2026-11-02）

## 问题与处理

项目编辑返回新的完整文档。此前即使机制没有变化，整个工厂、机制数组及嵌套配置也会被新引用替换，导致列表分组、拖拽数据和卡片一起更新。机制展开缓存虽然可以避免部分 IPC，仍无法避免这些响应式工作；显示时间单位还被包含在物理展开的缓存身份中。

现在对新 IPC 快照做结构共享：内容相等的分支复用上次发布的引用，只替换变化路径。旧快照不被修改；重复事件返回同一内容时直接结束刷新。删除字段、数组变序、对象/数组类型变化及 null 仍按新文档发布。刷新代次检查和数值求解缓存的失效判断继续保留。

物理展开的项目设置身份排除显示时间刻度、LP 后端和轨道运输价格。产能、邻接估算、品质、可达性、工厂环境和机制配置仍参与身份。卡片、太阳能信息及筛选索引使用明确的数值环境依赖；加载函数在 `untrack` 中调用，避免意外订阅整份项目文档。显式缓存清理另有响应式代次，换上下文后即使文档未变也会重新读取。

宇宙/普通工厂的求解签名按文档代次惰性计算和复用。宇宙预览缓存按作用域保存一份签名和 Promise，每个机制读取不再重新排序/序列化整个文档，也不再把完整签名编码进每次读取的缓存键。旧请求失败只有在仍拥有对应缓存条目时才能删除它，不能清除新请求。

## 对照测量

基线为 `f3c3305`，与本变更对照。使用相同的 600 机制文档，额外添加同项目的空工厂，分别停留在两者上执行项目重命名、切换时间刻度和修改采矿产能。每种情况采样六次，统计中位数；视口为 1600×1000，使用无头 Chrome。耗时包含发送、刷新及等待两个动画帧。

IPC 使用现有浏览器夹具模拟，因此数据衡量前端刷新/绘制开销，**不包含真实 Rust 展开、文件持久化或 LP 求解耗时**，不能解释为整个应用的加速比例。每种选中状态使用同一份完整文档，避免将文档大小不同误认为选中工厂的差异。

| 项目编辑 | 修改前：空工厂 | 修改前：600 机制 | 修改后：空工厂 | 修改后：600 机制 |
|---|---:|---:|---:|---:|
| 重命名 | 42.3 ms | 115.6 ms | 41.4 ms | 41.1 ms |
| 显示时间刻度 | 54.3 ms | 104.8 ms | 41.7 ms | 41.4 ms |
| 采矿产能 | 41.8 ms | 103.6 ms | 42.2 ms | 42.3 ms |

时间刻度编辑的可见机制展开请求从每次 **16 个降为 0 个**。数值产能编辑仍发起 16 个请求，不能为了减少请求而显示过期系数。所有项目编辑后，未改动的机制数组都保持引用身份。

原始样本：`local/project-edit-before.json`、`local/project-edit-after.json`；中间结构共享阶段为 `local/project-edit-shared.json`。表格使用六次样本的标准中位数，而非早期探针日志中的上中位数。基准受机器负载和帧调度影响，不把毫秒阈值写成 CI 断言。

可重复运行：

```powershell
node metatorio-app/tests/project-edit-benchmark.cjs
```

沿用浏览器夹具的 `PLAYWRIGHT_MODULE` 和 `BROWSER_EXECUTABLE` 设置。可选 `PERF_OUTPUT` 指定原始 JSON 输出路径；不设置时直接输出汇总。本脚本不依赖游戏或实际工程，不执行真实规划。
