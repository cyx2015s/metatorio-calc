# 传说虫卵与产能插件：相对平衡验收（2026-10-20）

## 输入与问题来源

用户样例 `local/lengend-prod.metatorio` 的副本保存在 `crates/metatorio-shell/src/mcp/auto_plan_assets_tests/fixtures/legendary-biter-prod.json`。目标分别替换为普通虫卵、传说虫卵、传说产能插件3，均为1/s，其余配置不变：Nauvis、传说机器、传说速度/产能/品质插件、1/8/1与8/8/16传说插件塔、严格供给与严格输出、普通生物助剂外部输入惩罚160。

原项目上下文 `0ac4e1f02224603e` 的实际缓存为 vanilla 2.1.19，而仓库默认 dump 为2.1.22。最终对照使用用户实际缓存，SHA256 `A7FF34BA440464CA93B52722FE89003C1091237457D06B31DD1D17843EBE3508`；没有修改缓存和源项目。模型有201393列、1648行。最初使用仓库 dump 的测量仅留作辅助诊断，不与实际上下文混算。

难例已经得到非负候选和精确可行的原模型对偶。紧凑候选只在六个物料平衡行留下约1e−16的逐行相对残差。旧路径仍为满足精确零而反复有理数修复，甚至冷启动；没有获得终止结果不能归类为无解。

## 默认验收与精确模式

用户明确同意逐行相对误差≤1e−12，并要求保留精确零模式。默认 rust-certified 尝试新路径；设置进程环境变量 `METATORIO_LP_BALANCE_MODE=exact` 可跳过新路径，使用原有精确验收。当前没有新增GUI开关；环境变量需在启动进程前设置。

等式的误差定义为：

`|A_i x − b_i| / max(|b_i|, Σ_j |a_ij x_j|)`。

`<=` 行只计正违反量。分子为零时误差为零，不设置绝对误差下限或 `max(1,...)` 的行尺度。每列重复系数先以精确二进制有理数合并，防止巨大相消项虚增分母。整段缺失的微小供应链仍会被拒绝。

快速路径只接受已有精确可行对偶的候选，其余交给原有修复流程。必要时从候选提示构造紧凑支持集重新搜索；这只是搜索提示，最终仍补齐全部原列，检查每一个原始约束。不是永久删除小系数、小流量或候选列。

验收同时要求：变量边界精确满足；全原模型对偶精确可行；精确候选和实际输出 f64 转回有理数后的点都满足逐行预算；成本与精确对偶下界的绝对差除以 `max(1,|cost|)` ≤1e−12。这个成本接近程度只是停止判据：原始点仅容差可行时，不能把它称作原 LP 精确最优值的严格上界。

报告新增 `relative_primal_verified`、`maximum_relative_balance_error`、`balance_tolerance`、`relative_duality_gap`。原来的 `exact_primal_verified`、`exact_optimality_verified` 保持严格含义；不精确可行时 `certified_relative_gap` 仍为空。运行时回写后的诊断只描述回写工厂；全候选模型的证据保存在LP捕获目录中。

## 未采用的实验

尝试了紧凑基先行、零目标可行性热启动、多个列生成换基策略、较大基的精确eta更新与浮点参数/列序组合。本样例没有显示足够收益，部分更慢；核心修改已撤回，实验补丁和日志仅留在local。不能把这些方法简单叠加当作保证成功的方案。

关于“如何区分真非零与计算舍入”的论文、证明边界和后续方向，见 [浮点残差验证调研](lp-roundoff-verification-20261020.md)。本次没有实现区间基验证或新的自适应精度点积。

## 最终版本验证续记

完成编译并关闭LP捕获写盘后，最终版本的串行单次端到端耗时为：普通虫卵10.018s、传说虫卵30.639s、传说产能插件3 38.495s。精确零模式单独用普通虫卵验证通过，12.759s。以上时间不包含上下文加载，包含枚举、求解与回写自检；仍非统计均值。精确模式不保证困难传说案例也能快速完成。

最终版本另一次启用捕获、伴随编译的三例运行也全部通过，分别35.102s、67.711s、42.520s，显示环境扰动明显。独立Python Fraction审计通过这三例的全部9份完整模型见证，原始和实际浮点点都通过逐行预算，全部变量边界及原模型对偶精确满足。

验收边界覆盖微小目标、整段缺失供应、重复系数相消、负变量、非法对偶、超出成本停止预算、零预算与浮点下溢，metatorio-lp共79项通过；metatorio-solver原有38项通过；两crate的lib/examples Clippy（`-D warnings`）通过。

交叉检查：Fulgora普通、传说、精良和混品四例全部通过，共12份见证重新复核通过，其中3份属于相对可行。lengden传说轻质框架样例通过，22.150s。Fulgora传说在受干扰运行中达到128.406s，最终版本复测119.243s，明显高于此前单次48.831s；后一轮首个浮点候选本身已耗43.91s，接近45s尝试预算并触发重试，无法仅归因为容差预检。这里保留该性能不确定性，不宣称所有场景均提速，也没有把重试或超时当作无解。
