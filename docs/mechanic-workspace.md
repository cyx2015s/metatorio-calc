# 机制工作区

## 展示与编辑边界

当前默认视图为 `list`，保留既有列表外观；工具栏提供「列表／网络」切换。

- `MechanicWorkspace.svelte` 是展示入口，负责公共筛选、空状态和视图分发。`mechanics/workspace.ts` 定义默认视图及 `MechanicViewProps`。
- `mechanics/workspace.svelte.ts` 持有与视图无关的筛选条件、展开索引、加载进度及失败重试。筛选 UI 只负责编辑条件。更换渲染器无需重建工作区；切换项目/工厂会清空条件，并丢弃旧批次结果。修改环境会重新建立索引。
- `MechanicListView.svelte` 独占配方分组、拖拽镜像、排序及行虚拟挂载。先筛选具体机制，再进行列表分组；分组保留全部机制 ID 和各自配置。筛选时暂停手动排序。
- `mechanics/actions.ts` 提供通用 `pick`、`pickFuel`、`addBeacon` 编辑意图，包括选择器预选、兼容性过滤、地格用途与插件槽校验。页面仅承接选择器请求和提示，不再分发机制类型。异步查询完成后若已切换工厂，不打开过期选择器。
- `runtime/mechanic-commands.ts` 是不依赖 Svelte、DOM 或当前选中对象的写操作接口：通过固定项目/工厂发送编辑消息，覆盖新增、克隆、删除、启用、排序、清理、各类参数与插件配置。`runtime.mechanicCommands(scope)` 创建实例，原有 runtime 方法委托给同一实现。多步排序跨越异步刷新时仍读取原工厂的最新快照；原工厂已删除时拒绝发送。
- `MechanicEditor.svelte` 独立提供左侧配置与机制操作，包含插件/插件塔和参数的二级菜单，不读取展开流。列表的 `MechanicCard` 组合该编辑器与右侧流量区；网络视图直接使用该编辑器。编辑器和 `ModuleEditor` 通过同一 `actions.commands` 写回，继续复用 runtime 的原型详情、本地化和图标。

后续添加其他视图时，扩展 `MechanicViewMode`，在工作区增加渲染分支并传入 `MechanicViewProps`。工具栏中的视图状态放在渲染器之外；展示偏好不进入工厂文档或撤销历史。每种视图独立管理布局、滚动或缩放，不修改底层机制来实现视觉聚合。

需要全工厂流信息的视图可令 `MechanicWorkspaceSource.needsAllFlows` 为真，复用每批 6 个请求的共享索引。普通列表仍按可见行懒加载，打开筛选才补全索引。索引经 `actions.loadFlow` 使用普通工厂的 `runtime.loadMechanicFlow` 或宇宙预览的同一在途请求缓存，失败不能按空流处理。索引中是系数为 1、每秒的净流，实际流量需乘相应求解用量；未求解与求解用量为 0 应区分。网络图的关系聚合不能丢弃品质、温度或燃料约束，也不能把依赖边当作求解器输出的点对点物流分配。

## 网络视图

参考客户 **stduuzurl / yoisaki kanade** 的独立网络可视化器（`playground/recipe-graph`），由 [YoisakiKanade222](https://github.com/YoisakiKanade222) 提供原始设计与实现参考。集成采用 Svelte 组件与现有工作区数据，不引入其 Python 代理或独立 Bridge。2026-10-19 从该公开 GitHub 个人页确认账号及公开用户 ID `327975025`，本次集成提交使用 `Co-authored-by: YoisakiKanade222 <327975025+YoisakiKanade222@users.noreply.github.com>`。

- 绘图使用 Cytoscape.js（MIT），分层布局使用 ELK.js（EPL-2.0，可选用该许可；依赖中保留原始许可）。两者按需导入，静态打包后可离线使用；初始列表不加载绘图引擎。ELK 使用独立 Web Worker，卸载时终止，布局不占用页面主线程。
- 机制、流和外部来源构成关系图。目标金边，隐式来源虚线，显式来源实线。默认隐藏公共能量与污染流；开启后其节点置于主生产链下方，相关边弱显且不参与主链布局。若电力或热量本身是目标，则始终作为主链显示。
- 品质、流体温度区间、燃料供需及燃尽产物约束保持不同身份。紫色虚线只表示与 Rust 规则一致的区间包含、燃料兼容和具名到任意流体能量转换，不表示已求解的转运量；不重新实现依赖原型数据的降温与提热辅助变量。
- 可选折叠仅用于非目标、非公共流，且生产与消费端各唯一的中间节点；边保留流身份以及两端各自的数量。多个物质不会变成一条无身份的边。
- 求解后使用各机制的实际用量；未求解时同组变体分别列出单位量，不能把替代方案的单位量相加。禁用与实际用量为零保留不同状态。
- 筛选和配方合并共用既有入口。点击节点/边时，在画布内靠近对象的位置显示非模态浮层；机制只渲染共享的 `MechanicEditor`，不重复流量区。浮层按屏幕像素定位，跟随平移、缩放、拖动及窗口大小变化，靠边时翻转或收进画布内。编辑以稳定机制 ID 跟随分组变化；子菜单/原型选择器的 Escape 不关闭父浮层，关闭父浮层后焦点回到画布。
- 搜索高亮画布，节点候选放在搜索框下拉列表中，支持上下方向键、Enter 定位、Escape 和外部点击关闭。取消独立节点目录和画布下方详情区。网络模式的流筛选面板浮动在画布右上角，收起后保留活动条件摘要，不占用画布布局空间；筛选无结果时仍保留画布和筛选控件。
- 工厂各自保存节点位置、缩放、平移、选择和图内选项，切换视图时恢复；列表和网络视图还各自保存工作区滚动位置。组件卸载清理 Cytoscape、ELK 与观察器，旧布局/图标请求不能更新新图。
- 画布采用屏幕实际像素比，缩放时重绘元素，滚轮使用 Cytoscape 默认灵敏度。节点文字跟随全局界面字体，纯数值流量标签跟随代码字体，字体设置修改后实时同步。平移/缩放只保存视口；拖动只保存该节点，完整位置快照留到重建与卸载时保存。
- 节点通过 Cytoscape 多层背景叠加品质角标，使用与列表相同的原型图标缓存。普通品质单独显示时不加角标，混合品质分组显示各品质角标和名称，不能把资源/地格错误标为其机器或投入物的品质。图标大小可选 75%～200%，只调整节点和角标尺寸，不改变文字字号、节点位置或画布缩放；偏好随工厂视图保存，PNG 同样包含角标和所选尺寸。
- 图例、求解显示边界与来源署名收进画布右下角的「图例」浮动入口，点击后弹出，不在底部常驻占用高度；署名直接链接作者的 GitHub 个人页。画布随工作区伸展填满剩余高度。
- PNG 导出的是**当前筛选和图内选项生成的整张网络图**，不受缩放和平移裁切，不包含临时编辑浮层、搜索下拉框或筛选控件。搜索只高亮，不删节点。导出时显示进度并防止重复点击，通过系统另存为对话框选择路径；原生 `save_network_png` 命令写入成功后才返回完整路径并显示在界面上。取消单独提示，导出错误不触发布局重试，可以再次导出。

## 外部输入快捷操作

外部输入面板的「免费电力与热量」通过现有外部输入消息分别设置 `Electricity`、`Heat` 的成本为 0，复用已有条目。环境资源的「禁用」将对应精确流保存为成本 `10¹²` 的手动外部输入，以覆盖隐式免费来源；这只是高成本抑制，不是硬约束。成本是内部单位常数，不随时间刻度或 MW 显示换算。该常数也是前端「已禁用」标记的识别约定，不新增后端字段；「撤销禁用」移除覆盖，恢复当前环境实际提供的隐式来源。

`external-input-shortcuts.ts` 在开始操作时固定项目/工厂作用域。`test:external-inputs` 验证幂等、复用、精确品质/温度和作用域；`test:external-inputs-browser` 模拟既有 IPC 验证按钮、撤销和时间单位独立性。后端及 MCP 行为不变。

## 列表布局

机制卡采用固定 72 CSS px 的两行布局，左侧保留各机制类型自己的配置，右侧统一展示流量。

- 第一行：机制图标、设备或流体等相关图标、机器插件与插件塔图标预览、机制参数入口。名称和品质保留在悬停详情及无障碍标签中。
- 第二行：机制类别、当前求解用量、总代价、启用开关、克隆与删除。非机器类机制用量标为“系数”，不统一标为“台”。
- 右侧分为输入、输出两条流带，按流量系数正负分区；电力、污染及抽象流也完整保留。流带可横向滚动和键盘聚焦，↗ 可查看带名称的完整流量。
- 插件、插件塔、温度、燃料等参数通过二级浮层编辑。浮层支持 Escape、外部点击关闭与焦点恢复；打开原型选择器时保留父级编辑器。
- 图标摘要按品质区分机器插件，插件塔显示实际座数及塔内插件总数。`share` 表示每座塔平均覆盖的机器数，只分摊耗电、面积，不改变插件效果。

## 长列表

机制超过 80 条时启用虚拟挂载：保留固定高度的轻量行壳和拖拽目标，只挂载视口及前后约四行范围内的完整机制组件。完整组件卸载后不会发起流展开、详情及图标请求；再次显示时复用现有缓存。

正在编辑或持有键盘焦点的行会被保留。桌面以中栏为观察根，窄窗口以整体工作区为根，跨断点时切换。配方合并时以实际渲染的组作为拖拽项，避免组数与原始机制数不一致。每个品质和配置变体仍独立显示、独立编辑。

这不是只保留几个 DOM 占位块的完整窗口化：行壳仍然存在，便于保留现有分组与拖拽行为。主要节省完整卡片的组件、图标、机制展开调用和渲染开销。

## 前端验证

选择器每次打开都是独立的编辑会话：父页面以请求对象作为 `{#key}`，替换请求时完整重建组件，包括尚未关闭时切换编辑对象。`kind`、`initialTab`、`initialName`、`initialQuality` 通过 `untrack` 仅初始化本地草稿一次；不使用部分同步的 effect。搜索、页签、品质和选中项由当前会话管理；目录数据或同一请求内的过滤条件更新不会重建组件。调用方应创建新请求对象来打开另一个编辑对象，不原地修改初始参数。

项目与工厂选择由前端维护：刷新时保留仍然有效的选择，缺失或被删除时回退到当前列表的第一项，仅在列表为空时保留空选择。切换项目会选择该项目的第一个工厂，重复点击当前项目则保留其有效工厂选择。导入、新建、撤销/重做与 MCP 外部修改同样遵循这个规则。

`new-project` 在同一次编辑中创建项目和默认空工厂；`dispatch.created.projects`、`dispatch.created.factories` 分别返回其 ID，撤销/重做会同时移除/恢复两者。默认工厂采用现有空工厂设置（Nauvis、无机制与目标）。`auto_plan` 的接口不变，仍只保留其配置后的一个规划工厂。

```sh
cd metatorio-app
pnpm check
pnpm build
pnpm test:icons
pnpm test:layout
pnpm test:selector-browser
pnpm test:mechanic-commands
pnpm test:mechanic-filter-browser
pnpm test:network
pnpm test:network-browser
```

`test:layout` 需要独立的 Playwright 环境，默认从 Node 模块路径加载 `playwright`；也可设置 `PLAYWRIGHT_MODULE` 为现有包的绝对目录。`BROWSER_EXECUTABLE` 可指定本机 Chrome/Chromium 的可执行文件，否则使用 Playwright 自带浏览器。测试自行启动和关闭本机 Vite 服务，端口可通过 `UI_TEST_PORT` 指定（默认 5197）。

浏览器回归使用模拟 IPC，覆盖 65 个混合机制和 1000 行长列表：固定行高、窄窗口、插件选择器返回、焦点恢复、温度写回、全部流量、启用切换、合并组键盘拖拽、视口挂载与编辑保留。它不验证原型数据或 LP 求解正确性，也不替代真实游戏图标下的人工阅读检查。

`test:selector-browser` 默认使用端口 5200，验证目录/流选择器的初始值、草稿编辑、目录刷新保留草稿、未关闭时替换请求后的完整重置，以及关闭后重新打开的预选恢复。测试通过程序点击被遮挡的背景入口模拟替换正在编辑的请求，以覆盖正常模态交互不易触发的复用路径。

共享操作回归还覆盖选择器策略在卡片之外复用、抽取/销毁地格用途、切换工厂后的异步过期请求，以及回调绑定原工厂。`test:mechanic-commands` 验证作用域不可随选择漂移、不同机制类型的消息路由、多步排序读取最新快照、原工厂删除、派发失败中止及插件配置写回。

网络浮层回归覆盖真实画布节点点击、只渲染左侧编辑器、平移时跟随节点、编辑后稳定保留机制 ID、原型选择器/子菜单的焦点层级、搜索下拉框及 Escape、筛选不改变画布尺寸、零匹配后继续筛选，以及窄窗口下浮层保持在画布内。

`test:network` 验证精确流身份、方向性兼容、实际/单位量口径、筛选后分组、折叠流、显式/隐式来源和千机制规模。`test:network-browser` 默认端口 5203，使用真实 Cytoscape 画布和 ELK Worker，模拟 IPC 验证懒加载、共享缓存及失败重试、图内编辑、筛选与跨视图状态、工作区滚动恢复、PNG 全图导出与缩放无关、窄窗口和无 CDN 请求。还在 2 倍像素比下验证画布分辨率、滚轮响应、平移时不遍历节点、保存的全局字体及实时字体修改。它不验证真实 LP 求解结果；设置 `NETWORK_SCREENSHOT` 可保存截图，测试图标来自模拟 IPC 的占位图。构建后设置 `NETWORK_PREVIEW=1` 可对生产静态资源运行同一套完整回归，验证分包与 Worker 路径。


## 普通工厂与宇宙工厂共用工作区

两种模式使用页面中的同一个三栏结构与中栏工具栏，不再用 `UniverseWorkspace`
覆盖普通页面。`FactorySidebar` 提供工厂/项目 tab，项目设置仍在同一处编辑；
`FactoryTargetsPanel` 统一目标、目标表达式、FlowRef、流选择器、温度区间、数量单位与拖拽。
右栏统一由 `SolvePanel` 展示成本、优化诊断、流平衡与不可解原因；宇宙结果额外显示地点。

`mechanics/located.ts` 将 LocatedMechanic 投影为展示条目，保留原 ID、地点与 transfer 标识。
该投影不写回文档，也不替换 runtime 的 selectedFactory。写操作经捕获的
`MechanicScope.kind = universe` 转换成 universe 消息；普通工厂仍走原 factory 消息。
两种模式复用 MechanicCommands / createMechanicActions 的选择器、兼容过滤、插件与参数编辑。
转移条目显示为火箭转移，用同一 MechanicEditor 编辑物品与地点，不暴露普通发射的槽位开关。
新增的克隆、转移物品编辑及表达式排序消息均参与既有撤销历史。

MechanicWorkspace / MechanicListView / MechanicNetworkView 不区分独立 UI 实现。
列表合并键包含地点；普通工厂仍按可见卡懒加载。宇宙的 `universe_preview` 一次返回所有
条目的单位地点流、太阳能配平信息和隐式来源，前端按上下文、项目设置、宇宙内容合并在途请求并缓存。
后端 `expand_located_mechanic` 同时供预览和 LP 使用，预览不运行求解器，包含停用条目，
单条配置失败不会抹掉其他条目的展开结果。

网络流节点的身份包含地点、品质和温度。不同地点的机制不合并，温度/燃料兼容关系不跨地点。
火箭转移连接地面与太空；太空物品到地面的免费投送显示为兼容虚线，明确不是求解器报告的
实际物流分配量。编辑、筛选与视图切换继续保留原机制 ID 的节点焦点。

宇宙编辑按 180ms 防抖自动重算；普通文档刷新不会无条件丢弃宇宙求解结果。
自动规划回写、撤销及外部消息改变宇宙数据时失效缓存，迟到结果不能覆盖后续编辑。

宇宙外部输入以 `LocatedExternalInput { id, flow: LocatedDualVar, penalty }` 存入
`UniverseDocument.external_inputs`，旧文件缺失该字段时为空。手动输入按完整的地点、
品质、温度流键覆盖隐式来源；不同地点互不覆盖。新增、编辑、排序和删除走宇宙消息，
参与撤销历史与 ID 分配/导入/克隆，自动规划保留这些来源与成本。没有机制而只有外部
输入的目标也允许进入 LP。极高成本仍只是抑制来源，不是硬禁止。

`UniverseInputsPanel` 显示 `universe_preview` 的隐式来源，修改成本或点击 + 可固化，
删除手动覆盖后恢复环境来源；支持添加任意流、温度范围和指定地点的免费电力/热量。
地点选择统一用 `LocationPicker` 的图标网格，展示使用 `LocationIcon`：星球复用既有
planet 图标，太空使用 `space-platform-starter-pack` 图标。文字名称保留在悬停与无障碍
标签中。网络画布用右上角地点徽标，左下角继续保留品质徽标，搜索仍匹配地点名称。

新增验证：

- `cargo test -p metatorio-runtime --no-default-features --features microlp --test universe_workspace --lib universe`
- `pnpm test:universe-workspace`（地点隔离、合并与转移关系）
- `pnpm test:universe-workspace-browser`（真实 Svelte + 模拟 IPC，三栏、编辑、目标/表达式拖拽、
  温度、规划回写、网络节点焦点、普通工厂隔离）

转移求解测试验证运力收支和非负约束：LP 允许分数次制造，1200 运力的配方为 1000 重量
转移只需执行 1000/1200 次，但零成本等价解也可以多生产运力；不强制余量恰为零或 200。
