# 两阶段枚举与惰性列生成实验（2026-10-22）

## 范围与结论

本轮在已有 `lp-exp` 分支开展；分支由 `a3e63bb` 快进到已抓取的 `origin/master`：`c1d7ecd21c015b064114f52a5db3c41183899126`。原有未提交的 `lengden` 测试入口改动已恢复，未提交或推送。

先用无插件/纯插件和多种能源建筑求基础解，再对基础解所用机制展开现有 comb，适合作为启动与启发式定价。但只扩展这些机制，不能证明保持全局最优，也不能把第一阶段的无解当作完整模型无解。非负成本、非负变量不能补足这一证明。

可证明的版本是：局部扩展优先，未使用的机制族仍保留在全局定价范围中；最终必须证实所有遗漏列都不能改善目标。它通常需要迭代，不能保证恰好两次求解完成。保证的是同一个完整候选集合上的最优目标值及得到一个最优解，不保证相同基、相同路线支持集，或保留所有最优解。

本轮增加两个 LP 内核可执行实验，尚未接入生产自动规划的惰性枚举，也未测得真实工厂的加速比。

## 当前实现边界

- `crates/metatorio-runtime/src/auto_plan.rs` 的 `enumerate_all` / `enumerate_recipes` / `module_combinations` 先生成机制候选；`pick_machines` 按偏好、打分、备选数量选建筑。
- `crates/metatorio-runtime/src/solve.rs` 的 `plan_auto_plan` 随后通过 `build_autoplan_problem` 展开全部候选，再调用求解器。
- `crates/metatorio-lp/src/columns.rs` 的 `solve_column_generation_with_control` 已实现受限主问题、完整模型上的约化成本定价，以及不可行时的射线定价。终止证书回到完整模型验证。它接收的 `Model` 已经包含所有列，所以能减少参与求解的列，却不能省掉上游全量枚举与展开。

因此新实验需要把“产生列”的边界向 runtime 移动，而不是在当前 LP 上再包一次只看活跃列的裁剪。

## 实验一：局部扩展漏掉最优路线

抽象生产 LP：产出至少/恰好 1，所有变量非负，每台机制成本都是 1。下面以恰好产出 1 测试。

| 机制族 | 纯配置产出 | 混合配置产出 |
|---|---:|---:|
| A | 2 | 3 |
| B | 1 | 4 |

仅纯配置时选 A，最优成本 `1/2`。仅扩展已选 A 后，成本 `1/3`。完整模型选 B 的混合配置，成本 `1/4`。即使第二阶段已精确求到其子问题最优，仍比完整最优贵。

测试 `active_family_expansion_misses_an_optimum_until_global_pricing` 逐个认证这三个精确结果，再让完整模型的列生成以局部扩展列集合为种子；全局定价会补入 B 的混合列，得到精确成本 `1/4`。

这是满足非负成本和非负变量的抽象反例，不声称表中系数直接对应某个原版插件配方。若要依靠游戏额外结构排除此类情况，必须另证每个遗漏配置可被保留配置在物料、能源、成本等全部维度同时支配；仅凭纯配置的名称或初次解中的用量无法证明。速度与产能/品质组合改变多种系数，也不能直接假定混装列位于纯装列的凸包内。

## 实验二：纯配置无解不代表完整模型无解

两个资源各要求净产出至少 1。三个机制净产出向量为 `U=(1,-2)`、`V=(-2,1)`、`M=(1,1)`，成本均为 1。

只允许 U、V 时，两条约束相加得到 `-(x_U+x_V) >= 2`，与非负变量矛盾；允许 M 时，取 `x_M=1` 即可，最优成本为 1。

测试 `infeasible_pure_variants_do_not_prove_mixed_variants_infeasible` 检查：纯配置的不可行证书对该子模型有效，但对完整模型无效；完整模型列生成从 U、V 起步后会引入 M 并认证最优。

这是抽象的候选集完整性实验，不意味着每种游戏配方都会出现这种净产出关系。

## 保持最优目标值的证明

先写成等式标准形，完整列集合为 J：

```text
min c^T x
    A x = b
    x >= 0
```

对包含少量列的集合 R 求受限主问题，得到原始解 `x_R` 和对偶解 y。如果：

1. `x_R` 对完整问题可行（遗漏变量设为 0；完整物料行仍满足）；
2. 对所有完整列 j，`r_j = c_j - a_j^T y >= 0`；
3. `c_R^T x_R = b^T y`；

则 y 对完整对偶可行，强弱对偶立即给出完整最优性。含不等式时还需遵守对应的对偶符号限制；这里用标准形避免混淆代码里的 `<=` 方向。

第 2 条就是全局定价的职责。只检查已用机制、只检查能源类别代表、或启发式搜索没有发现负约化成本，都不能替代这一条。可以先用浮点或启发式找负价列，但最终的“没有遗漏改善列”需要可验证的界或完整检查。

受限问题不可行时没有基础解可供局部扩展。应使用 Farkas 射线/Phase I 目标定价，寻找能破坏子模型不可行证书的新列。只有该证书通过全部完整列检查，才能报告完整无解；超时或定价未完成必须保留未解状态。

这些条件保证精确 LP 的最优目标值。当前应用允许的 `1e-12` 逐行相对物料误差是另一层验收政策，不能自动变成最优成本误差界；使用近似定价终止还须提供有效对偶下界与差距认证。

## 建议的工程路径

1. **固定参照全集。** 相对于当前 comb、品质、偏好、可达性、插件塔等规则定义完整候选集合。现有枚举降级是已知设计，本轮不改变。新增能源类别建筑如果超出现有 `pick_machines` 的输出，参照全集也要同步扩大，不能与旧全集混为同一个最优性声明。
2. **runtime 建立机制族与惰性列提供器。** 族标识至少区分配方/采矿对象、机器及品质、配方品质、插件塔条件。展开仍使用同一套成本、燃料、温度、环境逻辑；一个机制可能展开为多个 LP 变量，不能把两者视为一一对应。LP 内核只接收数值列、行标识、对偶或射线，不理解插件、品质和普通路线。
3. **小模型启动。** 在既定全集内选纯插件配置，并按需保留无插件配置；覆盖能源/燃料兼容分支和既有机制。无插件必须属于明确的参照全集，不能偷偷扩大。不同能源代表能降低初始漏路风险，但同能源的其他机器仍可参与后续全局定价，除非有严格支配证明。
4. **先局部定价，再全局定价。** 根据活跃机制族先展开 comb、加入改善列；局部找不到后，流式遍历其他族的允许 comb 并计算约化成本。只存入选列及必要缓存，避免把所有机制和展开列常驻内存。加入列后重新求解，新的对偶可能让此前不改善的族变得改善，所以全局检查不是一次性过滤。
5. **完整行与终止认证。** 固定稳定的物料/能源/温度行标识，完整目标、严格供给/输出、外部输入成本都保持同一语义；若同时惰性生成行，必须另做分离和全行可行性认证。无改善列且完整原始/对偶认证通过才报告全局最优；无可行解则走全局射线检查。

一种可证明的提前筛选例外：每个遗漏列都能表示成保留列的非负组合，等式行系数完全相等且组合成本不高于遗漏列，则任何使用遗漏列的解都可替换。对不等式也可放宽成相应方向的支配，但必须逐维证明；“基础解中没用到”不满足此条件。

## 性能实验验收建议

先加实验开关，比较同一冻结上下文和候选全集下的全枚举与惰性列生成。使用 release、单并发，同样的截止时间和精度；分开记录枚举/展开耗时、各轮求解耗时、全局定价耗时、峰值内存、生成及保留列数、最终目标和证书状态。使用已有传说目标难例与外部生物结晶对照，另加受限模型初始无解的情形。

主要预期收益是降低初始 LP 和常驻列的规模；全局定价仍可能遍历大部分甚至全部 comb，轮数也可能增加。因此目前不能承诺总耗时下降。先流式遍历作正确性基线，再考虑有证明的族级界，避免第一轮同时引入许多无法归因的优化。

本轮验证命令：

```powershell
$env:CARGO_INCREMENTAL='0'
cargo test -p metatorio-lp --release columns::tests
```

实际验收：`cargo test -p metatorio-lp --release` 全部 **84/84** 通过，包含本轮两个新增实验；`cargo clippy -p metatorio-lp --all-targets -- -D warnings` 通过。测试运行时间不是工厂性能测量，不据此推断加速比。
