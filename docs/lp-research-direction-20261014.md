# 稀疏 LP 与精确认证：路线评估（2026-10-14）

本轮是网络调研与源码静态核对，没有启动长时间复测、改变求解策略或证明人工土壤回退已解决。

后续用户通过新编译 GUI 验证人工土壤在多组配置下可用，并于 2026-10-14 确认 LP 实验收尾。本文的实验顺序是未来研究备选，不是待立即执行的任务；阶段验收与未确认项见 [实验收尾记录](lp-experiments.md)。

## 结论

浮点候选 + 精确原模型认证的方向有成熟研究支撑。现阶段应收敛实现与实验，而非继续串接恢复方法。不存在把所有优化加入后即可保证实际预算内成功的结论。研究中的算法保证依赖具体前提、终止规则和算术模型，不能直接转移给我们的启发式组合。

用户要求的是准确度和稳定性超过原实现；零容差有理数认证是当前实现选择的更强标准，不是这个产品目标的必要同义词。认证当前 f64 系数对应的精确有理数 LP，也不等于证明生成模型完全符合游戏规则；上游舍入与供给边界仍需单独检查。

## 研究与当前实现的对应

1. **稀疏修正单纯形。** Huangfu 与 Hall 的论文强调稀疏 LU、超稀疏线性系统求解、因子更新、对偶最陡边定价与 bound-flipping ratio test。原矩阵稀疏不保证基逆稀疏，超稀疏也需测量迭代中的向量密度。
   - 原文：https://link.springer.com/article/10.1007/s12532-017-0130-5
   - 本地：`crates/metatorio-lp/src/float.rs::refactor` 对结构块进行稠密消元，返回 `m*m` 显式逆。精确因子已有块分解，但浮点路径仍与成熟稀疏因子路线有差距。这是静态观察，尚无剖析证明它是人工土壤的首要耗时点。

2. **LP 迭代精化与按需提高精度。** SoPlex 用有限精度 LP 求解器解经过残差修正的相关 LP，结合精确运算；遇到数值困难时可提高算术精度。2023 年组合方法论文报告其测试集上比单独精化更稳、比单独提高精度更快，并非任意 LP 的限时成功保证。
   - 官方说明：https://soplex.zib.de/doc/html/EXACT.php
   - 2016 年论文：https://pubsonline.informs.org/doi/10.1287/ijoc.2016.0692
   - 组合方法：https://arxiv.org/abs/2311.08037
   - 本地：浮点基重建、原始/对偶精确验证、独立对偶配合辅助可行性修复，与混合精度思想一致。但现有 `refine_basis` 的精确换基不能直接视为已实现论文中的 LP 残差迭代精化；缩小容差也不等于增加有效算术位数。

3. **列生成的退化与稳定化。** 列多行少适合考虑受限主问题，但文献早已研究对偶不稳定、退化、长尾与稳定化。有效收益依赖定价、热启动、主问题处理及具体结构。
   - 综述：https://pubsonline.informs.org/doi/10.1287/opre.1050.0234
   - 稳定化：https://pubsonline.informs.org/doi/10.1287/opre.1060.0278
   - 本地：所有列已显式构建，当前列生成是在其中筛选，并非免除模块组合枚举的惰性建模。`lp_hybrid.rs` 在共享 1200 秒预算中先允许列恢复占最多 900 秒，再进行行生成，存在挤占既有成功路径的风险。人工土壤 891 秒成功变为 1207 秒未完成说明组合尚未达到稳定性目标；预算挤占是待消融验证的原因之一，不能先认定为唯一原因。

4. **其他算法家族。** Google 的 LP 指南将单纯形、内点法和一阶方法视为互补路线，也指出一阶方法更难取得高精度。PDLP 适合更大规模、低内存的近似求解，但不直接替代当前需要基与精确认证的路径。
   - 官方指南：https://developers.google.com/optimization/lp/lp_advanced
   - 当前优先级：暂不新增内点法或 PDLP 自研。先用成熟实现对同一冻结模型建立参照。

## 建议的低成本实验顺序

1. 冻结少量原模型：人工土壤、精良粉瓶、传说种子、最佳插件机械臂，以及一个已有完整无解证明的对照。复用现有输入，避免重新枚举和整套真实规划循环。
2. 把 SoPlex 精确模式作为外部参照；HiGHS 保留为浮点参照。导出时保留原始系数含义与足够精度，独立验证原模型；仅有浮点 solved 状态不算精确成功。此步骤尚未执行。
3. 只做三组消融：昨天保留基路线；今天原基分块/独立对偶修复、关闭列恢复；今天完整路线。各组固定预算、验收标准、输入和版本，记录成功/认证无解/未完成、耗时与峰值内存。
4. 仅对未完成实例记录换基进展、重复基、因子重建次数、浮点与精确算术耗时、有理数位长。根据最大耗时项选择下一项修改；循环、数值不稳定和有理数运算开销分开处理。
5. 新策略先保持实验开关。旧成功案例必须继续成功，新困难案例有可复现收益，才进入默认路径。换规则后停止重复循环与真正改善求解成功率分别验收。

近期应保留原基分块与精确验证这一已体现收益的主线，优先处理人工土壤回退和策略调度；暂停增加新的大型恢复算法。若成熟精确参照轻松解决而 Rust 仍超时，才投入定位其具体实现差距；若参照也困难，转向模型规模、退化结构和业务精度要求。
